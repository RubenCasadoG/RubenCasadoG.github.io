## **Reconocimiento**

La primera fase del reconocimiento es realizar un escaneo de puertos con `nmap`, para ver que puertos abiertos tiene la máquina.

```bash
nmap -p- --open --min-rate 5000 172.17.0.2 -n -Pn -oN allPorts
```

![picture](/assets/images/dockerlabs/raas3.png)

Realizo un escaneo más exhaustivo sobre los puertos abiertos encontrados, para comprobar la versión del servicio y lanzar una serie de scripts predeterminados de `nmap`.

```bash
nmap -p22,139,445 -sVC 172.17.0.2 -oN targeted
```

![picture](/assets/images/dockerlabs/raas4.png)

Listo los recursos compartidos con `crackmapexec` para ver si tengo acceso con una *null-session*.

```bash
crackmapexec smb 172.17.0.2 -u '' -p '' --shares 2>/dev/null
```

![picture](/assets/images/dockerlabs/raas5.png)

Pero compruebo que necesito credenciales para acceder al recurso **ransomware**, ahora la idea es intentar encontrar credenciales para el servicio `smb`, voy a utilizar la herramienta `enum4linux` para intentar listar usuarios.

```bash
enum4linux -U 172.17.0.2
```

Y encuentra 3 usuarios.

![picture](/assets/images/dockerlabs/raas6.png)

## **Explotación**

A continuación, voy a crear un archivo con los usuarios encontrados para realizar un ataque de fuerza bruta con `crackmapexec` sobre el servicio `smb`.

```bash
crackmapexec smb 172.17.0.2 -u users.txt -p /usr/share/wordlists/rockyou.txt 2>/dev/null | grep [+]
```

Y encuentra las credenciales para el usuario **patricio**.

![picture](/assets/images/dockerlabs/raas7.png)

Compruebo los permisos de los recursos compartidos del usuario **patricio**.

```bash
crackmapexec smb 172.17.0.2 -u 'patricio' -p 'basketball' --shares 2>/dev/null
```

Y veo que tiene permisos de lectura sobre el recurso **ransomware**.

![picture](/assets/images/dockerlabs/raas8.png)

Listo el contenido del recurso compartido y encuentro 3 archivos, 2 de ellos de texto.

```bash
smbclient //172.17.0.2/ransomware -U patricio
```

![picture](/assets/images/dockerlabs/raas9.png)

Me descargo todo el contenido con `mget *`.

![picture](/assets/images/dockerlabs/raas10.png)

En el archivo `nota.txt` encuentro un mensaje para el usuario **Calamardo**, y el contenido del archivo `private.txt` está cifrado, además del ejecutable el cual según el mensaje parece ser una `ransomware`.

![picture](/assets/images/dockerlabs/raas11.png)

A continuación, necesito realizar `Reversing Engineering` para intentar desglosar como funciona el binario, para ello lo abro con `ghidra`.

- ***Averiguar el algoritmo de cifrado***. 
	
	En la función `encrypt`, se puede comprobar el algoritmo de cifrado utilizado en el ejecutable, que es el `AES_256`.

	![picture](/assets/images/dockerlabs/raas12.png)
	
	Este algoritmo de cifrado necesita una **clave** de **32 bytes** y un **IV** de **16 bytes** (*Initialization Vector* > valor aleatorio que se utiliza junto con una clave para iniciar el proceso de cifrado), si la **Clave** y el **IV** se encuentran en el binario, podríamos desencriptar el mensaje.

- ***Búsqueda de la clave y el IV.***
	
	1. *Initialization Vector*
		
		En la función `main` encuentro los valores de `local_438 = 0x3837363534333231` y `local_430 = 0x3635343332313039`.
		
		![picture](/assets/images/dockerlabs/raas13.png)
		
		Si transformo los valores a formato `ASCII` obtengo los siguientes resultados.
		
		![picture](/assets/images/dockerlabs/raas14.png)
		
		Al ser la arquitectura del ejecutable de **64 bits**, el formato de los valores está en **Little Endian**, con lo que tendré que invertir el resultado. 
		
		Concateno el resultado, y compruebo que el resultado de los caracteres es **16**, por lo que estoy ante el **IV**.
		
		![picture](/assets/images/dockerlabs/raas15.png)
	
	2. *Clave*
		
		En la función `recon` se concatenan las siguientes cadenas.
		
		![picture](/assets/images/dockerlabs/raas16.png)
		
		Si las transformo a `ASCII` y las invierto, obtengo la siguiente cadena.
		
		![picture](/assets/images/dockerlabs/raas17.png)
		
		```bash
		y0qpfjxbd79047929ew0omqad3f4gscl
		```
		
		Si compruebo los caracteres de la cadena obtengo **32**, por lo que estaría ante la clave.

		![picture](/assets/images/dockerlabs/raas18.png)

- ***Desencriptado del contenido del archivo `private.txt`.***
	
	Voy a utilizar la herramienta [CyberChef](https://gchq.github.io/CyberChef/) para desencriptar el contenido, para ello necesito codificar la **clave** y el **IV** en `base64`.

	![picture](/assets/images/dockerlabs/raas19.png)
	
	Además de convertir a **hexadecimal** el contenido del archivo `private.txt`.
	
	```bash
	xxd -p private.txt | tr -d '\n'
	```
	![picture](/assets/images/dockerlabs/raas20.png)
	
	Ya con los datos convertidos, los introduzco en `CyberChef` y obtengo el contenido del archivo en texto claro.
    
	![picture](/assets/images/dockerlabs/raas21.png)

## **Escalada de privilegios**

#### Movimiento lateral de usuario

Accedo a la máquina con las credenciales encontradas mediante el servicio `ssh` como el usuario **bob**, listando los permisos de sudo del usuario puedo ejecutar el binario `/bin/node` sin la necesidad de utilizar contraseña como el usuario **calamardo**.

![picture](/assets/images/dockerlabs/raas22.png)

Y miro la web [GTFOBins - Node](https://gtfobins.github.io/gtfobins/node/), para ver como puedo ejecutar una `shell`.

```bash
sudo -u calamardo node -e 'require("child_process").spawn("/bin/sh", {stdio: [0, 1, 2]})'
```

Al ejecutarlo obtengo una `shell` como usuario **calamardo**.

![picture](/assets/images/dockerlabs/raas23.png)

#### Movimiento lateral de usuario 2

Buscando por el servidor, encuentro las credenciales del último usuario **patricio** en el archivo `.bashrc` del usuario **calamardo**.

![picture](/assets/images/dockerlabs/raas24.png)

#### Escalada de privilegios a root

Listando las `capabilities`, encuentro la `capabilitie - setuid` en un ejecutable `python3` dentro de la carpeta `.ssh` en el directorio personal de **patricio**.

![picture](/assets/images/dockerlabs/raas25.png)

A continuación, vamos a obtener una `shell` como usuario **root**, cambiando el valor de nuestro `user ID` a `0` (*el uid de root*), y ejecutando una `/bin/bash`.

![picture](/assets/images/dockerlabs/raas26.png)
